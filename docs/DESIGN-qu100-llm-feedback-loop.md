## 1. Problem & what already exists

Operator wants a closed loop: **(1)** log every LLM buy decision as a $10k paper trade, **(2)** track its exit (stop-loss / target / hold) and realized performance, **(3)** feed results back to the LLM daily + weekly to improve its judgment, **(4)** weekly, sweep all QU100 to find winners we *missed*, why, and how to improve.

The system is **~80% built** (see exploration 2026-06-01). Reuse, don't rebuild:

## 2. Goals / non-goals

**Goals:** turn `setup_long` theses into tracked $10k paper positions; close them on path-dependent SL/TP/hold with dollar P&L; surface realized performance into the daily/weekly LLM loop; weekly, attribute missed winners across the full QU100 and feed improvements back.

**Non-goals:**
- **No real-money trading / broker execution.** Paper only. (Phase 3 IB execution stays out.)
- **No look-ahead.** Entries fill at the *next* session's open; exits walk forward day-by-day.
- Don't replace the existing `ThesisEvaluation` fixed-horizon eval — the paper-trade tracker runs *alongside* it (different question: "what would the trade have made" vs "was the directional call right").
- No **core operational / raw paper-trade tables** move to Neon (legacy tables stay local; joins + hypertables required). The **only** permitted Neon write is the optional **Phase 4** mirror of `paper_report_snapshot` rows for a private website (D11) — never the raw operational data.
- No fine-tuning / model retraining — feedback is prompt-context + config-weight tuning + human-readable lessons.

## 3. Decisions (defaults chosen; ★ = please confirm at approval)

- **D1 — which theses become positions:** every `setup_long` thesis (top-5, afternoon+close sessions), **deduped to one open position per symbol** (no double-buy while open). Confidence gate: open only if `llm_confidence ≥ 6` (default **on**). **Same-symbol multiple `setup_long` in one day (operator 2026-06-02):** open the **highest-`llm_confidence`** thesis; tie → **earliest session** (afternoon before close). Deterministic. The other same-symbol theses are recorded in `paper_skip` (`reason='same_symbol_lower_conviction'`) so repeat-conviction isn't silently lost.
- **D2 — sizing:** fixed **$10k notional** per position, `shares = floor(10000 / entry_price)`, residual tracked as cash (no fractional shares). No portfolio cap on concurrent positions (each pick is its own $10k sleeve — this measures *per-decision* quality, not a capital-constrained portfolio). ★
- **D3 — entry price/timing + fill-validity guard:** fill at the **next session's open** after the thesis (T+1 open), reusing `qu100_portfolio`'s convention; avoids look-ahead. If the T+1 open is unavailable, the position stays `pending` until priced (or expires after 2 sessions). **Fill-validity guard (parallel-review P1 — the source engine has it at `qu100_portfolio.py:505-507`, the port dropped it):** if the T+1 open has already **gapped past** the levels (`open ≥ target_price` or `open ≤ stop_loss`), the setup is gone — do **not** open the position. Because the row was created `pending` at thesis-time, the fill step transitions it to **`status=expired`** (NOT left pending — a lingering pending would block the symbol's partial-unique slot) and records `paper_skip` `reason='gap_invalidated'`. Otherwise degenerate same-day round-trips (fill then instantly stop/target on the entry bar) would pollute win-rate and the day-0 `discover_time_stop` sample.
- **D4 — stop-loss / target source + PERSISTENCE (Codex rounds 1 P0, 2 P1):** use the screener candidate's pattern levels (`entry_price`/`stop_loss`/`target_price`/`rr_ratio`/`pattern_type`), which are pattern-derived and already drawn on the chart shown to the LLM. **They're dropped today** — `persist_screened_stocks` only writes `pattern_type`/confidence (`persistence.py:32`; note **`pattern_type` already exists** on `ScreenedStockRecord` `models.py:418` — do NOT re-add it). Fix in **two places**:
  1. **Persist the levels in the top-50 path** (`persist_screened_stocks`): additive migration adds `entry_price`, `stop_loss`, `target_price`, `rr_ratio` columns (NOT `pattern_type`); populate from each candidate. This is what the weekly miss-attribution (cap 4) reads — and it covers top-50, not just the top-5 thesis names.
  2. **Source the `paper_trade` from the persisted `screened_stocks` row**, not the in-memory candidate (Codex round 2 P1): create the trade via an **idempotent insert whose idempotency key is `thesis_id` alone** (`UNIQUE(thesis_id)` → `ON CONFLICT(thesis_id) DO NOTHING`, Codex rounds 3–4 P1). `screened_record_id` is **stored for provenance and as the pointer to the source levels**, but is NOT part of the conflict key. Read the levels from the persisted screened row. The Tier-1 idempotency cache can return an *old* thesis before evidence assembly (`service.py:319`), so the in-memory candidate may not match on a rerun/backfill — the persisted screened row is the stable source of truth. Creation happens in the post-scrape thesis path for each `setup_long` passing D1, as a DB-driven idempotent insert (safe to re-run the session).
  (Future option, not now: add explicit SL/TP fields to the LLM output and let it override.) ★
- **D5 — exit rules (port the *rules*, new pure evaluator — Codex round 1 P1):** `qu100_portfolio`'s exit code is portfolio/cash/rank/fractional-share driven and *skips entry-day exits* — it's **inspiration, not reuse-verbatim**. Build a small **pure, DB-backed `evaluate_exit(position, price_rows)`** that walks `stock_prices` from `entry_date` **inclusive** (the position is filled at the entry-day open, so intraday SL/TP **can** trigger the same day — Codex round 1 P1 on look-ahead): for each day in order, **stop-loss** if `day_low ≤ stop_loss`, **target** if `day_high ≥ target_price`, and an **optional learned `time_stop`** at `position.time_stop_days` (D6 — NULL when none learned yet → no time-exit; never a hardcoded default). **Same-day SL+TP → SL first** (conservative — note this is a known *downward* P&L bias on same-bar straddles; the daily report counts `same_bar_ambiguous_exits` so it's visible, not hidden). Applied on the entry day too. **Adjustment-basis (splits, operator 2026-06-02 = freeze):** booked `entry_price`/`exit_price`/`pnl`/`shares` are **immutable once set**; the position stores the price-adjustment basis it was booked under, and `evaluate_exit` for a still-open position must walk an OHLC series on the **same basis** as the booked `entry_price` (so a mid-hold split that auto-adjusts `stock_prices` cannot produce phantom stop/target hits against an unadjusted entry). **Gap-through:** if the day *opens* beyond the level (open ≤ stop, or open ≥ target), exit at the **open** (not the level). Otherwise exit at the level. Pure function over (position, ordered daily OHLC rows) → makes exits deterministic and unit-testable with fixture prices.
- **D6 — force-exit horizon is RESEARCHED, not preset (operator 2026-06-02):** **no hardcoded max-hold** (not 10, not 5). The optimal time to force-exit a position that hasn't hit SL/TP is **discovered empirically from the tracked data** and adopted as a *learned* time-stop. Concretely:
  - **Baseline (until a horizon is learned):** positions close **only on stop-loss or target** — they hold open with no time-exit. This is the data-gathering regime.
  - **Discovery (Phase 2 research, §5(3)):** a new research routine `discover_time_stop` reconstructs each position's **return-by-holding-day curve** from `stock_prices` (entry-day forward), and for each candidate horizon `k` aggregates over positions **still alive at day `k`** (not already SL/TP'd before `k` — Codex round 8 P2 survivor treatment). Hardening (parallel-review P1):
    - **Objective default = risk-adjusted** (return per unit of holding-period drawdown / a Sharpe-like mean·std of by-day returns), **not** mean return — mean-return just says "hold longer, line goes up" and ignores the drawdown you're exposed to. ★
    - **Min-sample gate = ≥ N *matured survivors per candidate `k`** (not N total trades) — the survivor cohort shrinks with `k`, and early runs would otherwise fit a handful of names.
    - **As-of guard:** the weekly reconstruction may only use prices up to the analysis as-of date per position (same discipline as `update_open_positions`), so the learned `k` isn't fit with hindsight.
    - **Recommend-only** until the chosen `k` is **stable across ≥2 weekly runs**; never auto-apply off a single small sample.
  - **Research wiring (Codex round 8 P1):** `discover_time_stop` plugs into the existing `research.py` machinery — add a new insight kind **`time_stop_discovered`** to `INSIGHT_KINDS` and a new action executor **`set_learned_time_stop_days`** to the executor registry (`apply_action`), mirroring the existing `disable_signal` pattern (gated/operator-approvable).
  - **Config (Codex round 8 P2):** add `learned_time_stop_days: int | None = None` to `LLMThesisConfig` (`config.py:293`); the `set_learned_time_stop_days` executor mutates it. Default `None` = no time-exit.
  - **Adoption scope (Codex round 8 P1):** the learned horizon applies to **future fills only** — a position snapshots `time_stop_days` from the config **at fill time** (NULL if not yet learned). Already-open positions filled before adoption keep their `NULL` (no retroactive mutation), so each trade's outcome stays honestly attributable to the rule it was opened under.
  - So the **mechanism** for a time-stop exists, but its **value is learned, never preset**. `evaluate_exit` exit reasons: `{stop_loss, target, time_stop, manual}` (no hardcoded `max_hold`). ★ objective + min-sample + auto-vs-recommend.
- **D7 — how feedback reaches the LLM:**

So tuning it is a placebo until `weight` is first **wired into** prompt rendering (e.g. ordering/emphasis of evidence) or a scoring path. Phase 2 must wire `weight` before any auto-tuning, or auto-weight-tuning is deferred. **Default: defer (b)**; ship (a)+(c) first.
  - **(a) plumbing (Codex round 1 P2; mechanism corrected by parallel-review P1):** add a bounded **calibration section** to `build_user_message()`, computed by the daily job and stored in a small `paper_calibration` row the prompt builder reads. **Its primary/headline stats are the unbiased `ThesisEvaluation` fixed-horizon numbers (see (a2))**, not realized-paper-only; the last K=10 closed paper trades are included as supplementary context **explicitly labeled realized-closed** (and accompanied by MTM-including-open) so the block never presents a survivorship-skewed win-rate as the headline. **Cache correction:** `compute_input_hash` hashes only the EvidencePack + image bytes, **not** the user-prompt text (`schemas.py:71`), so the calibration block is invisible to the Tier-2 `input_hash` cache. So the calibration block uses the existing **`ThesisEvaluation` fixed-horizon (1d/5d/10d) close-to-close stats as the unbiased signal** until a `time_stop` is learned, and the paper-book stats are reported as **realized AND mark-to-market-including-open** (never realized-only).

- **D8 — "missed winner" (weekly sweep) + attribution feasibility (Codex round 1 P1; window per operator 2026-06-02):** a QU100 symbol whose **forward return ≥ +10% over the prior completed 10-trading-day window** that we did **not** hold a paper position in. **Window = 10 trading days** (operator: 5 is too short to catch the move; unbounded is too costly in compute/$ for the sweep). ## 4. Data model (new, legacy engine)

`paper_trade` (**plain Postgres table**, one row per opened position; open→closed lifecycle):
- `id` BIGINT **PRIMARY KEY** autoinc (plain — NOT hypertabled, per D10).
- `thesis_id` FK→`analysis_results` (**`UNIQUE`** — one position per thesis), `screened_record_id` FK→`screened_stocks`, `symbol`, `scan_date`, `session_name`, `created_at`, `updated_at`.
- `status` ∈ {pending, open, closed, expired}.
- plan (set at creation, from the persisted screened row): `planned_entry_price` (the **pattern** entry level — Codex round 2 P1: do not overload `entry_price`), `stop_loss`, `target_price`, `rr_ratio`, `pattern_type`, `llm_confidence`, `verdict`.
- fill (NULL while `status=pending`; set when filled): `entry_date`, `entry_price` (the **actual T+1 open fill** used for sizing/P&L), `shares`, `allocated_amount` (≤$10k), `residual_cash`, **`time_stop_days`** (snapshot of the learned `learned_time_stop_days` config at fill; **NULL = no time-exit**, D6), **`price_basis`** (the adjustment basis the fill was booked under — D5 split-freeze; `evaluate_exit` for an open position walks prices on this basis). Booked fill/exit fields are immutable once set.
- exit: `exit_date`, `exit_price`, `exit_reason` ∈ {stop_loss, target, time_stop, manual}, `return_pct`, `pnl`.
- **Partial unique index** `UNIQUE(symbol) WHERE status IN ('pending','open')` — enforces one open position per symbol (Codex round 1 P1; `UNIQUE(thesis_id)` alone does NOT). A re-picked already-open symbol is skipped at insert (caught on the partial-unique conflict).
- **Skipped-pick ledger (Codex round 1 P1):** skipped `setup_long` theses are recorded in the **`paper_skip` table** (defined below) so the feedback **denominator** (buy signals acted on vs skipped) stays honest.

`screened_stocks` migration (additive, Codex rounds 1 P0 / 2 P1): `ALTER TABLE screened_stocks ADD COLUMN IF NOT EXISTS` for `entry_price`, `stop_loss`, `target_price`, `rr_ratio` only (**`pattern_type` already exists**, `models.py:418` — do not re-add); populate them in `persist_screened_stocks` (top-50 path). **Note `persist_screened_stocks` is `ON CONFLICT DO NOTHING` today (`persistence.py:56`)** — change to **`ON CONFLICT DO UPDATE`** the new level columns (Codex round 3 P2), at least when the existing row's level columns are NULL, so a re-persist of the same scan backfills levels rather than silently skipping. Create `paper_trade` **after** its FK targets (`analysis_results`, `screened_stocks`) exist. The partial-unique-on-`symbol` index is DB-race-safe **iff** the application catches the insert conflict and records the skipped-pick ledger in a clean transaction (don't leave the txn aborted).

Missed-winner findings: **reuse `ResearchInsight`** (it already has structured `action` JSON + the weekly cadence) rather than a new `weekly_miss` table, unless reporting proves it insufficient (Codex round 1 P3 — default: reuse, no new table).

`paper_report_snapshot` (D11, local engine): `id` PK, `report_type` ∈ {daily, weekly}, `as_of_date`, `payload` JSONB (the rendered report data), `created_at`; **unique `(report_type, as_of_date)`** (idempotent upsert per period). Reports re-render from this; no need to re-run the pipeline to reproduce a past report.

`paper_skip` (skip ledger, local engine — keeps the feedback denominator honest): `id` PK, **`thesis_id` UNIQUE** (DB-level idempotency), `symbol`, `scan_date`, `reason` check ∈ {`symbol_already_active`, `missing_levels`, `missing_screened_record`, `gap_invalidated` (D3), `same_symbol_lower_conviction` (D1)}, `created_at`. (Session/confidence-gated rejects are NOT skips — they're "not a buy signal", excluded from the acted-vs-skipped denominator.) Written when a `setup_long` (passing the confidence gate) is NOT opened — so "buy signals acted on vs skipped" is countable, not lost to logs. Idempotent per skipped thesis (`ON CONFLICT(thesis_id) DO NOTHING`). (★ alternative: derive skips from `setup_long` theses minus `paper_trade` instead of a table — operator's call.)

## 5. Architecture by capability (reuse → new)

**Daily job ordering (Codex rounds 2 P1, 3 P1).** The 17:00 PT job today is `run_daily_eval` (`scheduler/service.py:287`). Extend it to run, **in this exact order**: (i) **price ingest** (per-`(symbol,date)` upsert, D9) for **`(pending ∪ open) paper_trade symbols ∪ today's top-50`** — pending symbols MUST be included or a pick that drops out of the next day's top-50 would falsely expire (Codex round 3 P1); (ii) `fill_pending_positions()`; (iii) `update_open_positions()`; (iv) existing horizon eval; (v) reports + calibration write. Ingest must precede fill/update or the open will be absent. **This ordering is authoritative — all of §5 below follows it.**

**(1) Buy-decision tracking** — `paper_trade` (status=pending) is created in `service.compute_theses_and_persist` for each `setup_long` passing D1 via an **idempotent insert with `ON CONFLICT(thesis_id) DO NOTHING`** (matching the `UNIQUE(thesis_id)` constraint — Codex round 3 P1; `screened_record_id` is stored but is not part of the conflict key), reading levels from the **persisted `screened_stocks` row** (D4) — rerun/backfill-safe even when the Tier-1 cache replays an old thesis. The **daily job** then `fill_pending_positions()`: fills each pending at its T+1 open (D3) → status=open, `entry_price`/`shares`/`allocated`/`residual` set (D2). A pending with no T+1 open after 2 sessions → status=expired.

**(2) Exit + performance** — new `update_open_positions(date)` step (daily, step iii, after fill): for each `open` position, call the pure `evaluate_exit(position, ordered stock_prices from entry_date inclusive)` (D5); on trigger → status=closed with `exit_*`, `return_pct`, dollar `pnl`. Requires the step-(i) prices; idempotent (re-running a day doesn't double-close).

**(3) Feedback loop** —
- *Daily* (extend `run_daily_eval`, 17:00 PT): per the ordering block, fill/update (steps ii–iii) run **before** the horizon eval (step iv); then (step v) compute paper-book stats, send the daily report, and write the calibration block (D7a) consumed by the next session's prompt. (Do NOT run buy/exit tracking after the eval — Codex round 3 P1.)
- *Weekly* (extend `run_research_job`, Fri 09:00 PT): add paper-trade P&L as an input to the research checks; emit lessons (D7c) and, if enabled, weight-tuning actions (D7b). **Plus `discover_time_stop` (D6):** reconstruct each position's return-by-holding-day curve from `stock_prices` (entry-day forward), aggregate across closed+mature positions, find the holding-day `k` maximizing the objective, and emit a `ResearchInsight` recommending `learned_time_stop_days = k` (gated by a min-sample threshold; operator-approve or auto-apply behind the existing research-action gate). Adoption writes the config, which is read **at fill time only** to snapshot each new position's `time_stop_days`; `evaluate_exit` applies that **per-position snapshot** (never the live config), so already-open positions are not retroactively time-stopped (Codex round 9 P1 — future fills only).

**(4) Weekly miss-sweep** — new `sweep_missed_winners(prior_window)` in the weekly job (Fri 09:00): ensure full-QU100 prices (D9), compute each symbol's forward return over the **prior completed 10-trading-day window** (D8), flag winners ≥ threshold not held, then attribute *why missed* with the **data-availability tiers** (D8) — precise (verdict/pattern) for top-5/top-50, `rank_too_low` for the rest — joining `analysis_results` (verdicts), the migrated `screened_stocks` (pattern/levels), and `money_flow_snapshots` (full ranks). Write findings as `ResearchInsight` rows + a Discord report.

## 8. Risks / open questions

- **Price reliability** (yfinance gaps/splits) drives P&L correctness — ingest must handle missing/adjusted data; flag splits.
- **Entry realism:** T+1 open is a model; real fills differ. Document it as a paper assumption.
- **Sample size:** feedback (weight-tuning AND `discover_time_stop`) is noise until enough closed trades — gate on a min sample.
- **Indefinite holds (D6 baseline):** until a time-stop is learned, positions with no SL/TP hit stay open indefinitely, so (a) the `active` ingest set (pending∪open) grows over time, and (b) realized win-rate is over *closed* trades only (open positions shown as unrealized mark-to-market). Both are acceptable for a paper book; `discover_time_stop` is what eventually bounds hold time — empirically.
- **Methodological disclosures (parallel-review, surface in the report — not hide):** same-bar SL+TP→SL is a known *downward* P&L bias (counted via `same_bar_ambiguous_exits`); summed $P&L is "independent $10k experiments," not account equity (no cap, no fees/slippage); dividends/fees omitted (small downward bias on holds); the missed-winner metric is a coverage diagnostic only.
- **Splits/corporate actions = freeze booked fills** (operator 2026-06-02): booked entry/exit/pnl/shares immutable; positions store `price_basis`; `evaluate_exit` for an open position uses a consistent basis (prevents phantom hits from an auto-adjusted mid-hold split).
- **Scope:** combined Phase 0+1 first, then 2, then 3; operator may green-light only the first. ★
- **Open ★ decisions:** D1 confidence gate, D2 no-portfolio-cap, D4 SL/TP source, **D6 `discover_time_stop` objective (mean return vs hit-rate vs Sharpe-like) + min-sample + auto-apply-vs-recommend**, D7 feedback depth, D8 missed-winner threshold + attribution tier, scope (P0+P1 first vs all phases).
